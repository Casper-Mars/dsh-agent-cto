# 验收条件、返工与终止条件

`architect-tech-spec` 验收阶段的判据。逐项跑；不通过回到执行方案（第 3 步），同一项连续两轮不过则回到第 2 步检查验收条件。

## 一、7 项验收条件与通过线

| # | 验收条件 | 通过线（全部满足） | 证据形式 |
|---|---|---|---|
| 1 | AC 覆盖与归一化 | §3 每条 AC 一行；有来源（原文/推断/转述）；模块、接口、数据、验证四列非空；假设已入 §11 | 表格行号 + §11 |
| 2 | 数据模型 | 每字段有类型 / 可空 / 默认 / 含义 / 约束；索引对应具体查询；迁移有 up 与 down | §6 表名 + SQL 片段 |
| 3 | 接口契约 | 每接口有鉴权、幂等说明、限流、请求字段、响应、错误码（HTTP + 业务码 + 条件） | §7 接口名 |
| 4 | 关键流程 | 正常路径逐步编号；异常表覆盖超时、重试、重复提交、部分失败 | §8 场景行 |
| 5 | 部署 | 依赖与版本、env（名称/默认/必填）、发布顺序、灰度、回滚命令 | §9 段落 |
| 6 | 观测 | 日志字段名与示例、指标名与类型、告警阈值 + 持续时长 + 动作 | §10 条目 |
| 7 | 范围 | 非目标未被实现；没有验收条件外的「顺手优化」写成阻塞 | §2 与全文 |

任一不满足 → 回到第 3 步改执行方案；同一项连续两轮不过 → 回到第 2 步检查验收条件。

## 二、证据怎么写

- 必须是文档里的位置（章节号/表名）或命令输出，不能写「已检查」。
- 同一验收条件多条证据用分号分隔：`§6 export_job.status 默认 'pending'；§6 down SQL 存在`。
- 命令证据写命令 + 关键输出行：`pnpm migrate:down → exit 0`。

## 三、阻塞项格式

```text
[阻塞] 验收条件 3 / §7 POST /api/exports：无错误码与幂等说明。
要求：补 401/403/413/429/500 与 Idempotency-Key（24h）。
复核：同 key 连发 2 次，export_job 只新增 1 行。
```

输入不标准时（不构成阻塞）：

```text
[归一化] 输入：口头需求，无编号 AC、无 ADR。
处理：抽 AC1–AC5 标「推断」；架构选型列入待 CTO 决策；按最小改动继续。
复核：§3 来源列与 §11 假设清单齐全。
```

只有连问题都无法定义时才算阻塞：

```text
[阻塞] 输入：只有「做个报表」，说不出谁用、看什么、在哪看。
要求：业务方补齐角色、字段、数据源（截止 11-05）。
复核：§1 问题陈述能写成一句可判断的话。
```

## 四、不通过时的返工记录

```text
[返工] 条件 <n> / <章节>：<没过的证据>。
改法：<具体改什么>。
复核：<命令或检查点>。
```

规则：

- 写清「哪一项没过、证据是什么、改什么、怎么复核」。
- 一轮只改一类问题；改完立刻重跑该项。
- 连续两轮同一项不过 → 先修验收条件，不要继续打补丁。

## 五、终止条件

| 终止 | 条件 | 收尾动作 |
|---|---|---|
| complete | 7 项验收条件全绿 | 写 §1 结论与 §11，提交，汇报路径 + commit |
| blocked | 问题无法定义、仓库读不到、无权限做关键决策（PRD 不规范 / 无 ADR 不算） | 列出缺项与决策人，不改目标 |
| budget-limited | 达到迭代上限（默认 10 轮） | 保留返工记录，写清剩余失败验收条件，不谎报完成 |

`complete` 的报告不视为独立验证：评审仍需按验收条件复查。

## 六、循环纪律

- 目标一旦写下不改；要改目标 = 新开一次运行，并说明原因。
- 跨轮只依赖文档与输入材料，不依赖对话记忆。
- 每轮只碰一个验收条件对应的内容，避免全文漂移。
- 不为了「看起来完成」删除失败验收条件或降低阈值。
