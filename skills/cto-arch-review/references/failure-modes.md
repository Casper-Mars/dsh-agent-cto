# 常见架构失效模式

| 模式 | 表现 | 评审要点 |
|---|---|---|
| 单点 | 一个实例 / 一个库 / 一个密钥 | 是否有冗余与降级 |
| 级联失败 | 重试放大型雪崩 | 超时、退避、熔断、隔离 |
| 数据不一致 | 双写、异步补偿缺失 | 事务边界、幂等、对账 |
| 回滚失败 | 迁移不可逆、新旧不兼容 | 双版本兼容、回滚演练 |
| 容量拐点 | 线性假设、无压测 | 拐点数据、扩容路径 |
| 锁与并发 | 热点行、长事务 | 锁粒度、重试策略 |
| 观测盲区 | 出错无日志 / 无指标 | 关键路径埋点 |
| 权限扩散 | 服务账号过大 | 最小权限、审计 |
| 依赖锁定 | 单一供应商不可替换 | 抽象层、退出成本 |

## 用法

评审时至少逐条问「这里会不会发生」，命中就写进问题清单，不写泛泛的「注意风险」。
