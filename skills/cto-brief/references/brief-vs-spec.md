# 简报与技术方案的分工

同一份方案的两个投影。判据只有一个：**读者要不要拍板**。要拍板看简报，要实施看方案。

## 内容归属

| 内容 | 简报 | 技术方案 | 理由 |
|---|---|---|---|
| 结论（选什么 / 不选什么） | 必须有 | §1 结论 | 决定的第一入口 |
| 关键取舍与代价 | 必须有，≤3 条 | 方案选项与对照 | 决策的核心 |
| 「不做 / 维持现状」对照 | 必须有 | 方案选项 | 没有对照不算方案 |
| 一张图 | 必须有 | 总体设计 | 人靠图建立结构感 |
| 拍板点 | 必须有，带默认选项 | 未决项 | 简报的终点是把决定交回去 |
| 风险、反转信号、回退 | 必须各一条 | 风险与回滚 | 决定要不要现在做 |
| 数据模型 / DDL | 不写 | 全量 | 实施信息 |
| 接口契约 / 错误码 | 不写 | 全量 | 联调信息 |
| 部署步骤 / 环境变量 | 不写 | 全量 | 运维信息 |
| AC 覆盖表 | 不写 | 全量 | 追溯信息 |
| 影响面清单（文件级） | 最多一句范围 | 全量 | 执行信息 |

## 质量判据（可直接当验收用）

把简报单独给一个**没读过方案的人**，限时 2 分钟，看他能否回答：

1. 选了什么？排除了什么？
2. 主要代价是什么（复杂度 / 工期 / 风险）？
3. 他需要拍板吗？不拍板会怎样？
4. 最可能怎么错？看到什么信号回退？
5. 回退怎么退？

五问全答得出 → 简报合格。答不出的那一问，就是缺的那一段。

## 常见退化

- **缩写版方案**：按 §1–§11 等比压缩。错在保留章节结构，没重组为决策结构。
- **纯结论**：只说选 A，不说排除 B 与代价。等于替决策人做了选择还不给依据。
- **技术炫技**：把复杂度当卖点。决策人只关心代价与风险。
- **无回退**：风险写了，但没有「看到什么就退、怎么退」。
