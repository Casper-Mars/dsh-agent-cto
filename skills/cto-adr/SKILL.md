# 技术决策（ADR）

一次做一个决策点，产出可评审的 ADR 或结论。可评审的标准是：选项、代价、结论、证伪条件和退出条件齐全，用户能直接确认或推翻。

## 工作流程

1. **把问题写成可判断的一句。** 写清目标与成功指标、硬约束（时间 / 预算 / 合规 / 团队）、现状与痛点，并标可逆 / 不可逆。决策类型与必问约束见 `references/decision-catalog.md`。目标不清时退回目标，不比较方案。
2. **列选项，包括「不做」。** 至少两个选项 + 「不做」。每个选项按六维代价展开（`references/option-matrix.md`）：成本、工期、复杂度、锁定、运维、组织。事实与假设分开写，假设标证据等级。没有「不做」就没有基线，无法判断值不值得做。
3. **按约束取舍。** 结论先行；理由逐条对应第 1 步的约束，不用「行业最佳实践 / 大厂都这样」代替理由。不可逆决策必须同时给出退出条件、退出成本与回滚方式。风险与技术债记入 `references/risk-register.md`。
4. **设计证伪与复核。** 写清什么证据会推翻结论、什么时候复核、谁复核。没有证伪条件的结论不是决策，是偏好。
5. **自检并交付。** 按 8 项判据逐条验（见 `references/checklists.md`）。不过就补证据、补选项或改取舍。通过后按 `assets/adr-template.md` 生成 ADR 内容，按「输出」选择载体交付，停。多个决策点逐个跑本流程，最后按 `assets/roadmap-template.md` 汇总成路线图。

## 输出

ADR 或决策结论落在哪里，由当前场景决定，不要默认写本地文件：

1. **用户指定了载体**：要飞书文档就创建飞书文档并回链接；要本地文件就给路径；要贴到 Issue / PR 就贴到对应位置。
2. **用户没指定，但场景有明确载体**：在工作目录的 git 仓库里 → 写本地文件（默认 `docs/decisions/ADR-<n>-<topic>.md`）并提交；在飞书会话里且结论需要共享或留存 → 建飞书文档并回链接；只是要一个口头结论 → 直接在对话里给结论。
3. **判断不了**：问一句「要本地文件、飞书文档，还是只在对话里给结论？」；用户想先看结论时，先在对话里给摘要，确认后再落到选定载体。

默认优先级：有仓库且需长期维护 → 本地文件；需多人评审或共享 → 飞书文档；一次性判断 → 对话。无论落在哪里，最后都回一个可访问的位置（路径或链接）和 commit（如果有）。

## 规则

- 没有「不做」选项，或选项没有代价，不算完成。
- 不用「团队熟」当唯一理由；要算维护成本与锁定风险。
- 不可逆决策不能写「后续再评估」；那等于没有退出条件。
- 越过边界写 DDL、接口字段或任务清单，属于下游技能的产出。
