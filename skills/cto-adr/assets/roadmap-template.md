# 技术路线图模板

`cto-adr` 处理「未来 18 个月技术怎么走」时用。路线图不是功能清单，是一组决策的汇总。

- 决策人：CTO
- 关联 ADR：ADR-<n> ... ADR-<m>

|---|---|---|---|---|

## 二、写法规则

1. 每个技术主题必须对应一个业务目标；对不上的不进路线图。
2. 每个里程碑有可交付物与负责人；没有负责人的里程碑是愿望。
3. 能力缺口必须写补法（招 / 买 / 训 / 外包），只写「需要更强团队」没用。
4. 不做清单至少 3 条；没有边界的路线图无法执行。
5. 路线图只引用 ADR，不重复论证；论证在 ADR 里。

## 三、反例

- 把功能排期表当路线图——那是产品路线图。
- 主题写「微服务化」「上云」——没有业务目标和成功判据。
- 里程碑没有负责人和依赖。
- 预算只写「待定」——无法判断可行性。
