# 风险登记册与技术债台账

`cto-adr` 门禁 6 的配套。风险与技术债都写在一个仓库里，按季度复核。

## 一、风险登记册字段

| 字段 | 写什么 | 例子 |
|---|---|---|
| id | R<编号> | R12 |
| 风险 | 一句话，含触发条件 | 单库容量到 2TB 后写入延迟 > 200ms |
| 触发信号 | 可观测指标 + 阈值 | 库大小 > 1.8TB；P99 写入 > 150ms |
| 概率 | 高/中/低 | 中 |
| 影响 | 高/中/低 + 一句话 | 高：订单写入超时 |
| 缓解 | 已做/计划做什么 | 分库方案预研，Q2 上线 |
| 负责人 | 角色 | 后端负责人 |
| 复核日期 | YYYY-MM-DD | 2026-06-30 |
| 关联 ADR | ADR 编号 | ADR-7 |

等级由概率 × 影响决定：

| | 影响高 | 影响中 | 影响低 |
|---|---|---|---|
| 概率高 | P0 立即处理 | P1 本季度 | P2 观察 |
| 概率中 | P1 本季度 | P2 观察 | P3 记录 |
| 概率低 | P2 观察 | P3 记录 | P3 记录 |

## 二、技术债台账字段

| 字段 | 写什么 |
|---|---|
| id | DEBT-<编号> |
| 位置 | 仓库/模块 |
| 债务 | 当年为了什么妥协（一句话） |
| 成本 | 每月多花的人时 / 事故次数 / 延迟 |
| 偿还动作 | 具体改什么 |
| 偿还成本 | 人月 |
| 截止 | 日期或触发条件 |
| 负责人 | 角色 |

规则：

- 每条债必须能说出「当年为什么欠」，否则是缺陷不是债。
- 没有成本量化的债不进台账，进 backlog。
- 偿还动作必须能落到一个任务；写「重构一下」不算。

## 三、复核节奏

| 对象 | 频率 | 输出 |
|---|---|---|
| P0 / P1 风险 | 每月 | 状态变化 + 是否需要新 ADR |
| 全部风险 | 每季度 | 复核日期顺延或关闭 |
| 技术债 | 每季度 | 新增/偿还/延期，延期需写原因 |
| ADR 的证伪条件 | 按 ADR 的复核时间 | 保持 / 修订 / 取代 |

## 四、反例

- 风险只写「可能有性能问题」——没有触发信号，无法监控。
- 台账只增不减——没有关闭条件。
- 技术债没有成本——无法排序。
- 复核日期写了但没人看——复核人要写具体角色。
