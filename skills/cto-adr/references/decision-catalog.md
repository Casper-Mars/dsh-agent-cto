# 常见技术决策与必问约束

`cto-adr` 的速查。每类决策先问约束，再看选项；不从这里直接抄结论。

## 1 自建 vs 采购（build vs buy）

| 项 | 内容 |
|---|---|
| 决策问题 | 这项能力是我们的差异化，还是通用基础设施？ |
| 必问约束 | 三年总成本、上线时间、数据合规、团队维护能力、供应商锁定 |
| 不可逆点 | 数据迁移、合同期限、私有协议 |
| 常见错误 | 只比首年费用；忽略运维人力；把「能定制」当默认收益 |
| 退出条件 | 供应商涨价 > 30% / 无法满足合规 / 迁移成本可接受时 |

## 2 单体 vs 模块化服务

| 项 | 内容 |
|---|---|
| 决策问题 | 当前瓶颈是组织协作、部署耦合，还是性能？ |
| 必问约束 | 团队规模、发布频率、故障域、数据一致性要求 |
| 不可逆点 | 数据拆分、跨服务事务、对外接口 |
| 常见错误 | 用微服务解决组织问题；没有可观测性就拆分 |
| 退出条件 | 服务数 > 团队数 × 2 且协作成本上升时重新评估 |

## 3 云托管 vs 自建机房

| 项 | 内容 |
|---|---|
| 决策问题 | 成本曲线、合规要求与弹性需求哪个是主约束？ |
| 必问约束 | 三年 TCO、数据驻留、等保、峰值弹性、运维人力 |
| 不可逆点 | 数据驻留地、专线合同、硬件采购 |
| 常见错误 | 只算虚拟机单价；忽略网络出流量与人力 |
| 退出条件 | 月度云费超过自建 TCO 的 1.5 倍且持续 6 个月 |

## 4 数据平台：仓库 / 湖 / 湖仓

| 项 | 内容 |
|---|---|
| 决策问题 | 主要负载是 BI、实时、还是 AI 训练？ |
| 必问约束 | 数据量增速、实时性、团队 SQL 能力、成本 |
| 不可逆点 | 数据模型、元数据体系、存储格式 |
| 常见错误 | 先建湖再找场景；没有数据治理就上湖仓 |
| 退出条件 | 查询成本/延迟连续两季度超阈值 |

## 5 AI：调 API vs 自托管

| 项 | 内容 |
|---|---|
| 决策问题 | 数据能否出域？延迟与成本哪个是硬约束？ |
| 必问约束 | 数据合规、调用量、单位成本、模型更新频率、团队 GPU 能力 |
| 不可逆点 | 数据出域、模型微调资产、供应商合同 |
| 常见错误 | 用自托管解决合规却不做隔离；只比单次调用价 |
| 退出条件 | 调用成本 > 自托管 TCO / 供应商 SLA 不达标 |

## 6 团队结构：平台团队 vs 嵌入式

| 项 | 内容 |
|---|---|
| 决策问题 | 瓶颈是重复建设，还是业务响应速度？ |
| 必问约束 | 团队规模、业务线数量、平台成熟度 |
| 不可逆点 | 汇报关系、编制、职级体系 |
| 常见错误 | 平台团队没有产品经理；嵌入式团队重复造轮子 |
| 退出条件 | 平台需求排队 > 6 周 / 业务线抱怨响应慢 |

## 7 技术债：先还还是先做功能

| 项 | 内容 |
|---|---|
| 决策问题 | 债务的月度成本是否已超过偿还成本的分摊？ |
| 必问约束 | 事故频率、交付速度下降幅度、客户影响 |
| 不可逆点 | 数据模型错误、安全债 |
| 常见错误 | 用「重构」代替可量化的偿还目标 |
| 退出条件 | 债务成本降到可接受区间即停止专项 |

## 使用规则

1. 先写约束，再选类型；类型不匹配就自定义决策点。
2. 每类决策至少给出「不做」的现状成本。
3. 结论必须带证伪条件与复核时间，不从目录里抄。
